# Conditional delivery source analysis

`callscope/report_delivery_analysis.py` exports `analyze_pattern(analysis) -> dict` for the report-chain engine's fixed `conditional_delivery_result` dispatch. The exact locator-only contract is `delivery-rule.json`. The selected source functions match the original CodePatchBay report's distinction between execution success, terminal delivery and queue projection; the original prose is a provenance label rather than detector input.

The helper derives the conditional finalization formula, persisted-result selection, failure construction, callback installation, deferred capture, publication guards, verified-writer branches and reconciler validation calls from authenticated saved AST and actual CALLS edges. All intermediate names, field keys, Boolean formulas, callback arguments and result constructions come from source. Declaration identities keep similarly named local bindings separate. The finalization formula produces a finite truth table from the observed operators and literals.

The managed-worker layer selects the actual nested `main.processInbox` declaration and records the installed production callback separately from its activation, preserves cleanup/retention and fence guards, and connects the worker to assignment synchronization. The terminal writer distinguishes a newly created result from the source path that reads the same file, compares the existing canonical result with the intended one and throws on conflict. The reconciler's `this` attempt-reader site retains the authenticated raw CALLS edge and unique same-class candidate, with actual callee and runtime dispatch explicitly unproved. This is a source relationship between an observed invocation shape and an authenticated selected member body, not a repaired certain call. The reconciler preserves current-attempt selection, conjunctive finalizer validation, mode-dependent Git/journal checks, effective-result construction and recovery-plan conditions.

`pattern.components` exposes each layer's source result. `pattern.scoped_source_supported` is true only when the finite selected source relations are found and the engine budget is complete; the enclosing engine also requires authenticated role declarations and CALLS bindings. Source facts carry snapshot, source hash/span and stable content IDs through the engine. Unmatched required relations emit explicit gaps rather than negative functionality claims.

`source_execution_result`, `source_delivery_result` and `source_projection_result` remain separate. The analyzer does not establish target execution, remote success, receipt truth, global exactly-once publication, eventual convergence or completion of all recovery. Port outcomes and callback activation stay conditional. The applicability declaration retains disabled auto-finalization, cancelled/blocked/finalizer-only cases, publication conflicts and mode-dependent checks.

Validation uses a normal saved-source query of the full immutable v11 snapshot under the shared analysis lock. No target code is imported or executed, and no target or tool tests are run. The generated query artifact records the actual rule/helper/engine hashes and the source-derived finding; it is not a handwritten replacement for analysis.
