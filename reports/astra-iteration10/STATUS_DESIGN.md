# Automatic status classification against the original report

The benchmark is the superseded/terminal finding in the original CodePatchBay Astra analysis. Its complete scoped judgment needs the actual state producer, concrete predicate, recovery rejection, authoritative protection counterexample, and a separate recovery-policy interpretation. This implementation does not require approval from a new reviewer or replace the original report with a new acceptance denominator.

`callscope/status_analysis.py` provides `validate_status_rule(rule)` and `analyze_status_contracts(snapshot, rules) -> list[Finding]`. The exact contract is saved in `status-rule.json`. Five source-role locators select the producer, terminal predicate, recovery consumer, authoritative event append, and independent recoverability predicate. The business invariant supplies only the selected status and status/identity field names. Policies do not supply the handler name, Set members, intermediate calls, argument paths, branch results, or missing member lists.

Source inspection established the finite forms before implementation:

- The producer has a private static handler table, two actual indexed dispatch entries, argument/formal mappings, a selected status assignment, and event-to-state job identity assignments.
- The terminal predicate combines an optional identity read with a defaulted status Set membership test. Ordinary valid/missing identity cases are finite and give different results.
- The recovery consumer stores the normal result of an actual reader call in a const binding, calls the selected predicate with that exact binding, and uses a direct throwing branch. Its reader returns the selected component of an actual projection call. Both projection object-return branches are retained: direct materialization and checkpoint replay through the same handler table. No whole-object equality or collision-free digest theorem is needed for the conditional current projected status.
- The append callback reads events using the same root/project/job identity arguments, materializes them, and rejects a terminal current status with a nonallowlisted incoming selector. The selector is read from the current traced record, passed through its actual string normalizer, and tested against the actual imported allowlist. The direct null-return branch precedes the actual file-handle append call. Callback-result forwarding is followed through actual wrapper calls and normal return bindings to the outer return.
- The independent recoverability predicate remains distinct from terminal membership. Allowlisted handlers that write status are preserved, including the three approval-related handlers. Consequently the result concerns the current projection with the selected status, rather than an immutable history of terminal classifications.

The source analyzer authenticates original saved text/AST locations, lexical declarations, actual internal CALLS edges, and imported collection providers. It interprets only finite primitive status conditions, selected ordinary-record returns, static table lookup, direct branch completion, and standard Set membership. Captured receiver/alias writes, mutating methods, argument escapes, invalid source/bindings, unresolved necessary calls, unaccounted projection branches, and exhausted budgets prevent a complete result.

The explicit model retains ordinary data reads/writes, stable standard membership after the captured mutation audit, and normal data return/await semantics. It does not verify a running JavaScript environment, guarantee I/O or callback activation, replay event history, permit recovery, or claim protection of every journal or writer. These limits match the original scoped source judgment; they do not stand in for missing source relationships.

Each finding exposes all S1–S5 obligation certificates, separate source/model/policy evidence, conditions, refutations, necessary gaps, source budget, captured-source identities, and a derived judgment. `complete_assessment` requires all necessary relations and models to close. `full_goal_supported` additionally requires the original classification discrepancy and concrete terminal-guard rejection to hold. A complete comparison that refutes the original discrepancy receives `claim_refuted_or_narrowed` rather than a false supported result.

Normal source queries use the complete frozen v11 snapshot through immutable read-only SQLite and the shared query lock. `status-source-query.json` is generated by the analyzer and contains its exact module hash, saved snapshot/source/policy identities, and automatic evidence. No target code, target CLI, build, install, or test is run. This design note is documentation and is not an automatic witness.
