# Axon 与 CocoIndex 复用：独立静态评审

本报告评审 CallScope v0.3.0 对上游代码的实际接入、缓存正确性、版本证据和分发材料。评审者只阅读工具源码、已安装工具库的相关实现与保存产物，没有运行分析器、服务、测试、构建或浏览器。根代理正常运行 CallScope 读取目标源码所产生的观察另列；这不等于执行、导入或测试被分析项目。目标仓库保持只读。

## 当前判断

设计方向可以成立：复用 Axon 的图容器/索引，以及 CocoIndex 的持久计算引擎；CallScope 保留静态符号绑定、未知传播、规则语义与不可变发布。这种复用不自动提高语言解析完整性，也不证明功能正确。

按语言的完整输入集合缓存，是本版合理的正确性边界。同一语言内文件增加、删除、改名或内容改变时，应重建该语言全部词法/模块绑定；最终图整合与全项目规则每轮重新计算。它属于语言级缓存复用，不能宣传为已经解决文件级增量语义分析。

当前接入可以按上述有限范围交付，未发现剩余的确定 P0/P1 阻断。已经修正并复核上游 API 错配、包清单遗漏、Rust 运行失败被归入可缓存语法失败，以及进程实际版本和热修改身份风险。两库分别完成首次重算和再次持久复用，并保存了同快照去重的证据。

Axon 的复用范围较窄，主要是上游图模型与索引，尚未替代大型语言解析子系统；适配器仍生成兼容邻接列表，不能据此宣称内存或查询性能改善。CocoIndex 的前端缓存收益已有重复扫描观察，但“用了这两个上游”不自动证明架构判断能力更强，也不等于目标程序功能验收。

## 输入、缓存与身份必须保持的条件

| 条件 | 为什么需要 | 复核方式 |
| --- | --- | --- |
| key 包含该语言完整捕获文件集合与路径 | 仅比较改动文件会遗漏导出新增、删除、同名遮蔽、重导出与模块冲突 | 阅读实际序列化输入与失效规则，不接受默认三跳传播 |
| key 包含文件内容/哈希、捕获状态、整个有效政策、项目身份及实际解析实现版本 | 相同源码在不同根、别名、crate 映射、排除范围与解析器下可能产生不同关系 | 核对请求、CocoIndex 任务参数及返回结果的身份绑定 |
| 版本来自实际执行解析的进程 | 父进程和隔离 Python 的版本/语法依赖可能不同 | 子进程报告实际组件身份；不一致时拒绝结果或重新构造身份 |
| 前端只消费捕获文本 | 二次读取工作区会使缓存值与保存源码不一致 | 保持当前 `captured_files` 协议，目标路径只作数据身份 |
| 确定性解析失败与运行基础设施失败分开 | 固定输入的 grammar 拒绝可复用；临时引擎、进程或依赖失败不应永久缓存为成功结果 | 阅读异常与缓存提交路径，失败不冒充空成功图 |
| 缓存命中次数、耗时和工作进程信息不进入同 ID 的不可变事实 | 冷启动与命中可能产生相同语义结果，运行计数变化会制造同 ID 冲突 | 运行信息仅放服务响应/日志，保存分析事实可重复 |
| 每次成功发布只绑定一套输入、政策及版本 | 子进程结果、当前源码和历史图混合会产生没有来源的“半版本” | 核对请求指纹/实际版本、结果集合，再原子发布 |
| 失败保留最后已发布快照 | 缓存或子进程故障不能把旧结果包装为当前输入的成功结果 | 状态明确失败，旧快照仍按原身份提供 |

上述条件已沿 `analysis.py`、`analysis_inputs.py`、`cocoindex_runner.py`、`cocoindex_worker.py` 和 `service.py` 复核。每个语言 memo 调用接收语言、项目根、完整文件规范 JSON、完整有效政策及显式实现身份 JSON。实际 worker 版本用于快照，返回的语言集合、文件路径集合与源码内容/哈希/语言逐项绑定捕获输入。未按固定跳数或仅按变更文件重算。

`identity_json` 虽不在函数体中直接读取，仍参与 CocoIndex 全部参数指纹；当前没有配置参数排除。已核对安装的 `1.0.25` 相关实现：调用处在真正的 `App` / `Environment` 上下文，memo 只在成功返回后提交。仅有装饰器的普通直接调用不足以获得持久复用，当前实现没有犯这个错误。显式工具源码哈希覆盖辅助函数，不依赖对 `logic_tracking="self"` 的过度解释。

语法库在 memo 查询前初始化；运行失败错误码抛异常，不作为普通成功输出保存；含 `read_error` 的语言绕过 memo。固定源码的 grammar 拒绝可以缓存，仍保存为解析失败和部分覆盖。本轮修正了 Rust 对这两类失败的混淆，详见 U-03。

目标项目只作为 JSON 中的源码数据。runner 使用固定解释器、`python -I`、固定 worker 脚本和工具包工作目录，没有 shell 拼接；worker 显式加载可信工具包，前端只消费已捕获文本。目标路径和配置不成为动态模块名或命令，memo 输出限定为规范 JSON 字符串。缓存位于快照数据库绝对路径附加 `.cocoindex` 的位置；两库本次数据库在 CallScope 报告目录，因此未写入目标仓库。

这是目标代码不执行的边界，不是操作系统安全沙箱；工具本身、CocoIndex 原生引擎和语法库仍会正常运行，工具安装环境是可信前提。缓存含源码和分析结果，不能当作不含源码的统计文件分发。

服务在扫描开始和发布前核对模块加载时的工具源码指纹；worker 和总分析器也核对分析期间的指纹。源码变化须重启/重扫，避免把旧已加载模块与新磁盘身份混合发布。运行时命中、重算、未缓存语言清单仅进入服务响应/状态；同 ID 快照不包含这些变化计数。`full` 与 `cocoindex` 维护来源不同，产生不同快照 ID 是合理的，同一引擎的冷、热运行才要求同输入同 ID。

缓存跨语言复用目前成立的前提是各语言前端独立绑定，跨语言运行关系继续未知。如果以后加入 TypeScript↔Rust FFI、生成模块或共享 schema 推断，输入依赖需要扩展；现有按语言拆分不能自然涵盖这些关系。

## Axon 图核心复核

已阅读 `callscope/_vendor/axon/model.py` 与 `graph.py`，来源标记为 commit `2b386fb38a468201ab2ec825ddea5ebf4c33f513`。当前接入材料只有图模型与内存索引；没有据此宣称复用了 Axon 的完整解析器或架构判断能力。

上游 `KnowledgeGraph` 用节点/关系 ID 建索引，不自动验证调用语义。`add_relationship` 接受不存在的端点，重复 ID 会覆盖；`GraphNode.is_dead` 是可填写字段，也不代表上游完成死代码证明。CallScope 适配层仍须保持原有规则：仅有明确内部绑定、两端点都存在、源/目标非歧义的调用进入确定邻接；未知候选、外部边界与回调单独保存。现有节点/边身份和确定性排序不能因更换容器被重建成另一套含义。

已核对 `axon_adapter.py` 与修改后的 `GraphIndex`：确定边通过 Axon 建立关系，`outgoing/incoming` 从上游标签、关系类型和双向邻接索引生成；旧独立邻接追加路径已移除。适配层返回原 `Edge` 对象，保留原 ID、节点键顺序及排序规则。未知、回调、缺端点和重复声明处理仍使用原分支，Axon 对象不写进快照。没有将 `is_dead` 或其他上游默认字段当作新增判断。

初稿调用了上游不存在的 `KnowledgeGraph.get_relationship()`，会使首次加入确定边失败。通知负责人后，已改为适配层私有关系 ID 集合；上游源码未被改写，修正版中调用的方法均能在当前 vendor 源码对应。

## 许可与包装

已核对 `pyproject.toml` 包含 `callscope`、`callscope._vendor`、`callscope._vendor.axon`，以及 Axon 许可、来源 JSON、原 pyproject 和 `third_party` 数据。worker/runner 是主包普通 Python 模块；CocoIndex 固定为可选依赖 `1.0.25`。这是分发声明静态核对，没有构建 wheel 或验证安装产物。

Axon 原提交的 pyproject 明确声明 `license = "MIT"` 和作者；来源记录如实说明上游树没有独立 LICENSE。当前附带标准 MIT 条款和作者署名，没有声称复制了一份不存在的上游文件。CocoIndex 附带官方 Apache-2.0 完整文本、发行版/提交、wheel 哈希与已安装关键源码哈希记录；本评审核对本地记录，没有重新联网验证发行映射。

本地 `sha256sum` 与 Axon 来源清单一致：`model.py` 为 `4c08aa32a93dbd1a66da2f89c161904fd0205cdf5372527f8cc0dc4e2e85c2ee`，`graph.py` 为 `23f4f7f40eb8daa08ec8280276e36f7b415296790db745536e81da2f2685d55b`。最终来源记录的本地改动仅为命名空间导入适配及末尾空白格式，不声称两份本地文件都与上游字节完全一致。本报告不把来源与条款核对扩大为对所有上游权利状态的法律保证。

两库所有轮次仍是 `partial`。CodePatchBay 的 3 个 TypeScript 语法失败和 3 个不支持 shell 文件，以及 WinWinCode 的 6 个 TypeScript/JavaScript、6 个 Rust 解析失败都保留，没有因命中缓存变成完整覆盖。发现总数不是确认的架构缺陷数量，工具语法不支持也不是仓库功能错误。

## 尚未验证与后续边界

- 本轮没有实际修改、增加、删除或重命名目标文件，也没有注入解析器失败、损坏缓存或切换语法依赖。相应失效和故障处理判断来自源码与引擎 API 审查；冷、热观察不等于这些变化场景均已实测。
- 完整政策和全部工具源码哈希会使规则、无关语言或工具改动额外触发前端重算。这是当前正确性优先的保守选择，不是错误缓存；优化时必须先说明哪些输入可以安全从键中剥离。
- 语言独立缓存不能自然涵盖未来跨语言 FFI、生成器或共享 schema 的语义依赖；加入这些能力须扩展输入依赖协议。现在对应运行关系继续未知。
- `auto` 优先选择已准备的隔离解释器；若只有解释器文件而 CocoIndex 安装不完整，会选中后失败并保留旧快照，不静默切换引擎。当前已安装环境没有触发此条件；可显式使用 `full`。
- 当前审查及观察针对可信工具环境和本地既定扫描流程，未验收并发多写者、分布式任务、缓存迁移、长期资源增长或热升级。采用上游引擎不会自动获得这些保证。
- 缓存不会修复现有语言模型缺口。静态路径仍是显式结构见证，`unknown` 不等于功能缺口；两库的源码事实基准也不是维护者新增的架构要求。

交付应保持“直接复用上游图核心及持久语言缓存，在现有静态模型内保存可追溯结果”的口径。暂缓文件级增量、跨语言运行关系推断、热升级、多写者扩展及性能承诺；优先维护已经可说明、可保存、可复核的正确性边界。
