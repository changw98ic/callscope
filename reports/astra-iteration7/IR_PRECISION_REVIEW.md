## Primary recommendation

`FieldSummaryBuilder.eval` allocates an object literal before evaluating its property initializers (`field_summaries.py:480`). `invalidate_reachable` broadens any unbounded reachability result to every object (`semantic_ir.py:587`) and both damages and escapes those objects. An unfinished ordinary literal parent is a separate source domain: its result reference has not yet been assigned, returned, passed, or stored. A future `let`/`const` initializer binding cannot expose this current object before completion; an assignment initializer still exposes the old binding value. A property value or shared child does not imply a reverse child-to-parent edge.

Represent this lifetime on the actual allocation with a source-linked guard and explicit begin/end transitions. Exclude such a parent from fallback-only damage/escape. Preserve actual explicit roots, aliases, and construction operations that affect that parent. End the lifetime before normal assignment/return/call exposure. Avoid restoring a closed shape afterward from raw key text: closure must survive the actual ordered state transitions and be queried from the resulting `ObjectVersion`.

`unknown_captures_escaped` and `escaped_bindings` must remain separate from the temporary parent lifetime. A callback may capture a future binding, be retained externally, and reach the finished object after binding. Protecting the construction period must not suppress that later escape. Conversely, a wildcard damage operation should not manufacture a current parent edge merely because an unknown future capture could exist.

Delaying allocation until all initializer values are evaluated is another viable representation, but copying spread sources at that later point is unsound. Capture each spread's source version and selected copied value at the actual evaluation step; retain shared child identity and then materialize the destination from those observations. Finished nested temporary children may require their own private-temporary domain for deep precision. The outer parent's own-key proof does not depend on proving those children unchanged.

## Further precision losses

- External-domain closure is lost at joins unless every branch is represented. A bounded external alternative combined with `null`, `undefined`, or another certified primitive has no additional referents. A recursive domain-complete predicate can preserve this fact without asserting object plainness, property presence, contents, truth, or completion. A new recursive `_external_domain` implementation was observed during this review; its primitive alternatives still need deliberate treatment.
- Binary arithmetic normal results are primitives after the already-recorded operand/coercion effects. Returning an unbounded referent-bearing unknown for them creates artificial heap reachability. Record primitive content uncertainty separately.
- Captured cell writes and mutations of the cell's object referent are different. The current effect replaces every captured binding with `ir_captured_binding_write_possible`, including source-authenticated immutable bindings. Represent binding mutability and exposure explicitly; keep referent mutation and future-cell escape. Merely removing capture effects would be unsound.
- Missing module/function-declaration cells should not become missing caller-local capture edges. An authenticated module declaration cannot lexically acquire an unexposed caller-local temporary. Its possible external/escaped reach still matters. A genuinely missing local capture, recursion, or unauthenticated scope must retain its unknown domain.
- Branch-only allocations are retained as conditional by `join_states`, and `_project_version` refuses them even when the chosen value alternative witnesses the allocation's existence. Preserve branch/state/reference correlation if improving this case; do not globally remove conditional-allocation barriers. The actual `ports` parent exists before its initializer branches, so this is a separate generic issue.

## Soundness constraints for implementation review

Do not equate unknown field values with unknown own-key presence. Equally, do not equate a fresh object with a permanently private object. A completed object can be passed as an argument, captured through a cell, inserted into an exposed container, or returned and then mutated. Those actual allocation edges must remain effective.

Copy-time observations must retain their source allocation and version. Later writes to the old source can change shared child contents, but cannot retroactively rewrite the destination's already-copied own slot. Open copy surfaces, getters/Proxy effects, `__proto__`, computed keys, unsupported syntax, budget failures, direct eval, async assimilation, missing returns, and genuine capture uncertainty must continue to have explicit supported premises or remain unknown. A construction-private parent does not make its initializer calls pure or prove that execution reaches the return.

Any resulting `maxRetries` absence for the services return is a local conditional source judgment. A copy into the eventual `runJob` argument must independently establish the ordered copy and subsequent parent effects. It does not prove a numeric retry budget, an effective consumer, function activation, async fulfillment, message transport, or full functionality.

## Candidate construction implementation review

The subsequent source candidate records `ObjectVersion.construction_guard`, authenticates it during allocation, removes private construction allocations only from fallback widening, and calls `finish_construction` before the literal result leaves expression evaluation. Existing damage is retained at finish. The candidate also joins external domains recursively with primitive zero-referent alternatives and includes the actual callee value among opaque effect roots.

An initial candidate join inherited the first branch's construction guard across differing object versions. The reviewer reported this before freeze: joining a finished lifetime with an active lifetime could retain protection depending on hash order. The root's source correction was then read: conditional-allocation joins clear the guard; differing-version joins preserve it only when every participating version has the same guard; private construction selection rejects conditional allocations. That issue is resolved in the inspected correction.

No further blocking construction leak was identified by this source inspection. Actual reached allocations are excluded from the private set; reflection, exhausted reachability, incomplete state, escaped objects, and external-aliasable objects receive no construction protection. The adapter releases the lifetime before binding, return, or argument exposure. Ordered shallow-copy operations still capture source versions at the original evaluation step. `escaped_bindings` and unknown future capture escape remain active after finish.

The public IR currently relies on the adapter to finish before a normal bind; defensively clearing an active guard when the object is bound, escaped, or reused would make that invariant easier to maintain. Escaped and reused flags already disable the current protection, so this was communicated as hardening rather than a further demonstrated adapter leak. These judgments are source-level and do not certify execution, test behavior, or runtime object semantics.
