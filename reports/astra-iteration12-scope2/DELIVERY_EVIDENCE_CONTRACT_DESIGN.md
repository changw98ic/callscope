# Finite frozen candidate / role / evidence-source contract slice

This addition is a data-only rule for the existing `guarded_call_sequence` model, not a new analyzer, detector or acceptance rule. The 14 locators select actual production Rust declarations for the verdict composition, canonical Evidence resolution, direct candidate commit source, runtime source resolution, role requirements, checkout attestation and identity projections. All fields, calls and guard predicates are computed or retained by the existing authenticated CST report analyzer. The rule configures no expected fields, accepted roles or success predicates.

`message_identity_relations` was considered and rejected: its recognized chat/worker/outbox role groups do not represent these delivery evidence functions. Reusing one of those group names here would describe an unrelated model. The generic source sequence model honestly retains direct-source statement order, Result-try continuation, explicit abrupt guards, actual call operands, source locations and authenticated/unknown call-site distinctions. It does not manufacture a field-correlation theorem.

The selected production sources contain three distinct seams to inventory:

- Frozen commit: the frozen candidate getter exposes the captured field; direct candidate Commit evidence retains `candidate_ref` and `candidate_commit_id`; checkout comparison rejects a commit/tree/repository mismatch. These are source fields and comparisons, not proof that a repository was actually checked out.
- Roles: runtime/checkout identity constructors retain the terminal role together with WorkRun, attempt, lease, fencing and worker/session identifiers. Verdict composition invokes the explicit required-role selector. Source role labels and equality checks do not establish role authority, permissions or runtime authenticity.
- Evidence sources: the structured finding resolver iterates evidence sources, obtains a source event, checks source order, constructs an `EvidenceSource::Runtime` operand, and sends it to the canonical resolver. Runtime and direct-candidate source branches remain distinct. Missing, ambiguous, type-mismatched, candidate-mismatched or out-of-position sources have explicit rejection paths; existence of these guards is not evidence of actual input truth.

`query_delivery_evidence_contract.py` takes the shared internal query lock once, reads the real closed v13 saved WWC snapshot, invokes normal `analyze_report_claims` on this one new rule, and passes those actual generated Findings to normal `build_project_report` and `render_markdown`. There are no fixture or fabricated Finding records. The output is a development scope slice; the original v13 snapshot/policy identity remains unchanged and a new formal scope publication is still necessary. Current core bytes are checked against the existing 65-file freeze before and after the query. No target module, test, build or runtime is invoked.

Any partial binding or missing field remains partial/unknown in the actual saved Finding. The existing normal sequence assessment concerns selected conditional source structure; it is not whole-contract functionality, all roles, all evidence sources, complete permissions or full publish-boundary proof. Source fields may be retained as exact captured CST excerpts when the existing generic model cannot expand a Rust record or macro into a closed field projection. That limitation must remain visible rather than being fixed with a hand-written conclusion.
