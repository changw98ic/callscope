# 独立静态实现审查

本文件由独立审查代理维护。审查依据为 `docs/IMPLEMENTATION_CONTRACT.md`、共享模型以及逐步完成的实现源码。

用户硬边界：只根据源码中的静态调用结构分析；不执行或导入目标程序，不运行测试，不触发构建、动态追踪或沙箱。此次审查同样只读取源码；允许使用文本检索或 AST 语法读取，不把未经运行验证的实现描述为运行通过。

## 审查结论状态

已完成协议、主要实现及多数修正的源码复核。本报告区分“源码中已看到修正”与“程序已经运行通过”；本独立审查没有后者的证据。

最终判断：可以按 **Python 显式静态调用结构检查工具的首版** 交付。源码索引、声明规则、调用路径、版本证据及人工处置组成的闭环值得保留。它不是业务功能正确性检查器，也不应继续使用原 v1.0 的“全项目数字孪生”暗示分析完备性。下列已定位缺陷均已看到对应修正，当前没有已知未处理的交付阻断项；这不是对实现无缺陷或运行通过的保证。

## 实现复核重点

1. **执行边界**：仅文本读取和 `ast.parse`；不存在导入目标模块、运行目标命令、测试、构建或动态验证入口。应同时检查自动扫描、CLI、HTTP 和 MCP 入口。
2. **作用域与目标解析**：参数、赋值、导入、重定义和条件定义的遮蔽不会被猜测为唯一目标；方法体中的裸名称查找不会错误进入类作用域；继承、回调、装饰器、构造器和动态属性不会被推断成必然调用。
3. **负面结论**：未解析关系、解析失败、跳过源码、模块名碰撞和外部回调边界不会被当成确定缺失。结构路径存在也不说明业务正确或路径可实际执行。
4. **全量性**：规则检测不受展示用子图深度影响；图遍历不使用固定跳数作为正确性边界；路径截断和未找到有明确区别。
5. **版本与证据**：源码、配置、分析器和检测器版本绑定；查询固定快照；证据只从保存的源码读取；快照发布原子且发现不串版本。
6. **人工决定**：决定与快照及发现共同绑定；接受风险、误判和计划修复不会修改原始事实或检测状态。
7. **接口一致性**：模型字段、解析状态、检测状态、REST 参数、CLI/MCP 输出与前端引用一致；空结果、部分扫描和错误均不能显示为“功能正确”。
8. **扩展契约**：新增分析器或检测器需声明支持范围、未知语义和版本，而非只输出相同形状的节点与边。

## 结论边界

- 静态源码审查可以定位实现逻辑和接口缺陷，不能据此声称程序已运行成功。
- 解析得到的调用结构是受限模型。特别是 Python 的动态修改、外部回调及实例分派，不能从有限源码索引一般地恢复成确定运行行为。
- 用户禁止运行测试、目标程序、构建及动态验证。正常启动 CallScope、让它只读扫描源码或提供本地界面，本身不等于执行目标程序，不在这个产品禁令之内。
- 本独立审查角色采用更窄的工作方式：只读源码与 AST 语法读取，未启动工具服务、执行扫描、操作浏览器或运行测试。其他实现者正常使用分析工具的情况，应由其分别说明，不能与本审查的工作范围混淆。
- 上表状态只表示相关修正在源码中成立；未据此发布准确率、性能、浏览器兼容性或运行稳定性数字。

## 对需求与架构的独立判断

用户把功能可通过性置于性能之前，合理的落实方式是先保证结论语义、证据归属和功能闭环，而不是让“找到调用链”代表功能通过。调用结构最多回答“代码中存在这条显式连接”“声明的连接在当前模型中未找到”“还有无法解析的边界”。它不能判断参数是否正确、顺序是否正确、分支能否同时成立，更不能凭空推导未声明的业务需求。

因此，真实可交付的需求是：维护者声明结构意图，工具持续保留源码及调用关系，指出约束冲突或证据缺口，再由人核对。这项需求成立。若期待在没有规格、没有类型/数据流约束、没有执行证据的情况下判断一般功能完整性，则需求与信息条件不相容，增加图数据库、LLM 或可视化规模不能解决。

| 处理 | 内容 | 理由 |
| --- | --- | --- |
| 保留 | 显式调用/路径规则、源码位置、未知原因、不可变快照、版本差分、人工决定 | 直接支撑可核查的维护决策；首版已有明确输入和结果语义 |
| 修正 | 全项目数字孪生→配置范围内的静态索引；行为差分→静态结构差分；异常分数→规则事实和不确定性 | 防止名称承诺超过证据能力，避免把严重程度与可信度混成一个数 |
| 保留 | Python 单语言、全量重扫、SQLite、单机本地界面、同一服务边界 | 优先保障可解释性和实现闭环；没有证据表明首版需要分布式图存储 |
| 推迟 | 增量失效传播、其他语言、插件能力协商、分布式任务、多用户部署、自然语言查询、统计异常 | 这些需要先有清晰能力契约和真实使用数据；不能以固定三跳替代正确的依赖失效 |
| 删除 | 沙箱、执行差分、测试接入、构建验证、运行追踪、T3 执行证据及 verify API | 与用户当前硬边界冲突，不是等待后续自动恢复的功能 |
| 删除当前承诺 | 自动证明功能正确、一般终止性、完整运行时调用图、百万节点交互及低延迟数字 | 当前证据和实现均不足以支持这些承诺 |

与常见“应立即上成熟分析引擎/图数据库”的意见不同，本次不把组件替换列为优先事项。此次发现的主要错误来自符号语义、未知传播和版本归属，换存储不能修复。反过来，保守地输出更多未知也不自动等于产品成功：若真实项目大部分关键路径未知，仍需改进特定语言或框架的静态解析能力。

## 仍成立的条件风险与未经验证的假设

以下不是已确认的运行故障，也没有通过运行实验排除。

- **模型边界**：当前调用图是词法绑定近似。任意 monkey patch、隐式特殊方法、框架注册、复杂继承和运行时模块替换不在完整性保证内。已知不确定情形已尽量显式呈现，但审查不能证明全部语言特性均被正确降级。
- **采集一致性**：快照保存本次读到的文件集合。工作区同时修改时，文件可能来自不同瞬间；数据库原子发布不等于源码原子捕获。固定版本判断应使用稳定源码目录。
- **平台与部署**：首版读取依赖 POSIX 文件描述符接口，文档已注明 Windows 原生未适配。本地单项目串行扫描与不可变发布是当前边界；多进程共同调度、多用户权限及远程服务需要额外设计。
- **资源与扩展**：全量快照保留源码，图索引及多数查询在内存处理。项目和历史增大时，存储量、浏览器载荷、重复遍历及取消机制都需要观察。性能目标最低不等于可以忽略资源耗尽，但在未见真实瓶颈前不建议加入集群。
- **能力协议**：共享 dataclass 和注入式 analyzer/detector 是可扩展起点，不等于多语言插件已完成。新增实现必须声明覆盖范围、分派假设、未知与截断语义、版本身份；不能只满足节点/边字段格式。
- **实用性假设**：需要真实维护者核对规则是否表达其意图、未知比例是否可接受、证据是否减少定位工作。此次没有数据支持检出率、误报率或效率提升数字。此类判断可基于人工标注源码与正常只读工具使用积累证据，不需要执行目标程序。

## 首版验收边界

以下是交付应满足的检查准则，不是本审查宣称已经运行通过的结果。正常使用 CallScope 读取源码和人工核对保存证据，可以在不执行目标程序、不运行测试套件的前提下进行。

1. 支持范围明确：Python 源码、配置的 roots/exclude、平台条件及未支持能力均可见；空目录、失败文件及无法解析调用不会显示为业务正常。
2. 四种规则遵守“每个 source 至少一个 target”的显式量词，路径至少一条边；缺少端点、确定结构违反和相关未知有不同解释，规则不受图展示深度限制。
3. 每条已解析路径能回到对应快照的源码位置；动态/歧义候选不充当已解析路径见证。结构环不能被称为无限递归。
4. 同输入去重；配置、解析器、分析器、检测器或模式变化进入快照身份。旧证据不读当前工作区，异版本比较明确不可比原因。
5. 人工例外绑定具体快照和发现，不改写图事实；前端切换版本后不会展示无标签的旧查询结果。
6. CLI、HTTP、MCP 仅提供静态操作；没有执行、导入、构建、测试或沙箱入口。工具自身正常启动不能被描述为目标功能验证。

本次静态审查支持交付上述有限首版。对已发现的确定缺陷已完成源码复核；对模型覆盖、实际操作稳定性、使用效果和规模上限保留未验证状态。
